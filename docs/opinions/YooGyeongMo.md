# YooGyeongMo 의견/회고

## 개별 의견 (내가 맡은 파트의 기술적 판단)

- 맡은 파트: 프로젝트 뼈대, config 설계, CI/품질 게이트, 보고서 자동화, 통합
- config.yaml + Pydantic 검증을 가장 먼저 세웠다. 모든 단계가 설정 객체 하나만
  주입받게 하면 데이터셋이 바뀌어도 코드 수정 없이 파일 하나로 전환되고,
  잘못된 설정은 실행 전에 검증 오류로 잡힌다. 실제로 가설 변수와 유의수준,
  분할 비율 전부 config에서만 관리됐다
- 제공된 로딩 코드를 그대로 쓰지 않고 검증한 것이 가장 큰 수확이었다.
  na_values=" ?"는 skipinitialspace와 충돌해 결측 0건으로 보이는 함정이었고,
  수정 후 실제 결측 4,262셀을 잡았다. 이후 Polars가 파일 끝 빈 줄을 null 행으로
  읽는 문제도 실데이터 로그의 동일성 검증값(행수 일치=False)으로 발견해 고쳤다.
  검증값을 계산만 하지 않고 로그로 출력해 둔 설계가 버그를 드러냈다
- 보고서를 손으로 쓰지 않고 Jinja2로 자동 생성한 판단: 수치를 옮겨 적는 사람이
  없으므로 보고서와 코드가 어긋날 수 없고, make run 한 번으로 항상 최신이 된다

## 팀 의견 (협업 방식 회고)

- 이슈 먼저, 브랜치는 이슈 번호로, PR은 CI 통과 후 머지라는 규칙을 처음부터
  강제한 것이 좋았다. main 직접 푸시를 브랜치 보호로 막아두니 실수의 여지가
  구조적으로 없다
- 서로 다른 파일을 만지는 작업(로딩/시각화/통계+ML)은 브랜치를 병렬로 진행해도
  충돌이 없었다. 단계를 모듈로 분리한 구조 덕이다
- 자동 생성 보고서(사실)와 이 opinions 폴더(사람의 해석)를 분리한 것도
  유효했다. 수치는 파이프라인이, 의견은 각자가 PR로 낸다

## 배운 점

- 평균 검정만으로는 결론 문장을 지지할 수 없다는 것. 평균은 6.36시간 차이인데
  중앙값은 두 그룹 모두 40시간이었다. "고소득자가 더 오래 일한다"가 아니라
  "고소득 그룹은 초과근무자 비중이 높다"로 해석을 수정해야 했고, 차이는
  분포의 꼬리에서 온다는 걸 밀도 히스토그램이 보여줬다
- 대표본에서는 p-value가 거의 항상 작아지므로 효과크기(Cohen's d)를 함께
  봐야 한다는 것. p는 차이의 실재, d는 차이의 크기라는 별개의 질문에 답한다
- 합성 데이터 테스트가 전부 통과해도 실데이터에서만 드러나는 문제가 있다는 것.
  테스트 픽스처는 원본의 지저분한 특성(파일 끝 빈 줄)까지 재현해야 한다

## 개선 의견 (시간이 더 있다면)

v1 상태는 docs/reports/report-v1.md에 실행 캡처와 수치 크로스체크까지
박제해 두었다. 개선 후 무엇이 달라졌는지는 이 문서와의 대조로 증명한다.

우선순위 순서로:

1. 비율 검정 (가장 먼저): 핵심 해석 "고소득 그룹은 초과근무자 비중이 높다"를
   아직 직접 검정하지 않았다. hours > 40 이진화 후 카이제곱으로 비중 차이를
   검정해야 "평균 검정 > 해석 수정 > 수정된 해석의 재검정"으로 논증이 닫힌다
2. 외부 검증: UCI가 제공하는 별도 홀드아웃 adult.test(16,281행)로 최종 평가.
   같은 파일을 쪼갠 내부 평가보다 정직한 일반화 성능이다. 라벨 끝 마침표라는
   함정이 있어 검증 스토리 재료도 된다
3. 신뢰구간 보고: p와 d에 더해 평균 차이의 95% 신뢰구간을 병기해 효과의
   크기와 불확실성을 한 번에 전달
4. 교차검증 5-fold: 단일 8:2 분할의 운을 제거하고 성능의 표준편차까지 보고
5. 오즈비 해석: 로지스틱 회귀 계수를 오즈비로 변환해 어떤 피처가 소득 확률을
   밀어올리는지 표로 제시. 상관 히트맵에서 세운 가설(신호는 범주 변수에 있다)을
   모델이 배운 내용으로 확인
6. 교란변수 통제: 교육수준과 연령을 통제한 다변량 분석으로 근로시간의 순수
   효과 분리. 대시보드(Streamlit)와 스케줄 자동화(GitHub Actions cron)는
   그 다음 단계
