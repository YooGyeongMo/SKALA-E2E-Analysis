# seoyeong5864 의견/회고

## 개별 의견 (내가 맡은 파트의 기술적 판단)

- 코드를 보면서 왜 이 변수를 가설로 선택했는지, 이 검정 방식이 적절한지 등을 의견으로 내고 같이 고민해보는 과정 자체가 의미가 깊었다.
- 특히 Levene→Welch t→Mann-Whitney U→Cohen's d로 이어지는 검정 절차와, 보조가설(age)에는 사전 시각화가 빠져 있다는 점처럼 코드만 봐서는 지나치기 쉬운 부분들을 짚어보면서, 내가 직접 짜지 않은 코드라도 적극적으로 뜯어보고 의견을 내는 게 팀 전체 결과물의 완성도를 높이는 데 도움이 된다는 걸 느꼈다.

## 팀 의견 (협업 방식 회고)

- 정해진 담당 파트만 각자 맡아서 끝내는 게 아니라, 완성된 코드를 각자 직접 실행해보면서 보완할 점을 스스로 찾고, 그렇게 찾은 의견들을 다시 모아서 공유하는 방식으로 협업했다. 덕분에 한 사람이 놓친 부분을 다른 사람이 코드를 돌려보다가 발견하는 식으로 서로 보완이 됐다.
- 각자 실행 환경이나 관점이 달라서 같은 코드를 봐도 잡아내는 포인트가 달랐는데, 이렇게 여러 사람이 직접 돌려보고 의견을 모으는 과정 자체가 코드 리뷰 이상의 효과가 있었던 것 같다.

## 배운 점

- 같은 데이터셋이라도 어떤 변수를 가설 검정의 대상으로 삼느냐에 따라 분석이 전달하는 메시지가 완전히 달라진다는 것을 체감했다. income(소득 그룹)을 기준으로 어떤 변수를 비교해야 스토리로서 의미가 있을지 고민하는 과정에서, 단순히 상관계수가 높은 변수를 고르는 게 아니라 "이 차이가 왜 발생했는지 설명할 수 있는가"까지 따져봐야 한다는 걸 알게 됐다. hours-per-week를 주 가설로, age를 보조가설로 선택한 것도 이런 고민의 결과였다.
- 가설을 세우는 것과 그것을 "제대로" 검증하는 것은 다른 문제라는 걸 배웠다. 평균 차이가 있어 보인다고 바로 t-test를 돌리는 게 아니라, 먼저 등분산 여부(Levene)를 확인하고, 분포가 정규분포에서 벗어나 있는지(hours-per-week의 40시간 봉우리 같은 경우)를 살펴본 뒤에야 어떤 검정 방식(Welch t vs Mann-Whitney U)이 적절한지 판단할 수 있다는 절차를 몸으로 익혔다.
- 표본 크기가 클 때는 p-value만으로 판단하면 안 된다는 점도 인상 깊었다. 데이터가 3만 건이 넘다 보니 아주 작은 차이도 통계적으로 유의하게 나올 수 있어서, Cohen's d 같은 효과크기 지표로 "통계적 유의성"과 "실질적으로 의미 있는 차이"를 구분해서 봐야 한다는 걸 새롭게 알았다.
- 시각화와 검정은 순서가 있어야 한다는 것도 깨달았다. 검정 결과만 숫자로 보고하면 왜 그런 결론이 나왔는지 설득력이 떨어지는데, 박스플롯·히스토그램으로 분포를 먼저 눈으로 확인하고 나서 검정 결과를 보니 "왜 이 검정 방법을 선택했는지"가 훨씬 명확하게 이해됐다.
- 머신러닝 자체는 이번에 처음 접해봤는데, 데이터 정제 → 탐색적 분석/시각화 → 가설 검정 → 모델링 → 리포트로 이어지는 전체 파이프라인의 흐름을 경험할 수 있어서 좋았다. 특히 가설 검정 단계가 모델링 전에 "이 변수가 정말 타깃과 관계가 있는가"를 미리 확인하는 역할을 한다는 걸 알게 되면서, 통계 분석과 머신러닝이 별개가 아니라 하나의 흐름 안에서 서로를 뒷받침한다는 걸 배웠다.
